## 💥 Знакомая боль?

Ты кидаешь AI-кодеру задачу. Получаешь **хрен пойми что**. Докидываешь контекст — **чуть теплее**. Ещё 5 уточнений — **ну почти**. Через полчаса переписки ты уже хочешь просто самому всё написать.

**Спойлер: AI тут ни при чём. Проблема в контексте.**

Каждый токен в промпте — твой бюджет. Плохой контекст сжирает лимит впустую. AI не экстрасенс — он не дочитает твои мысли.

**TCE** — системный метод упаковки задачи в self-contained промпт, который AI-кодер переваривает с первого раза. Без переписки. Без «а ещё...». Без мата в три часа ночи.

### Шаг 1 — 8 вопросов Тарика Шехипара

Система вопросов, которые выковыривают **скрытые требования**, о которых ты сам не подумал:

| # | Вопрос | Что вытаскивает |
|---|--------|----------------|
| Q1 | **Какой конкретный результат нужен?** | Что должно лежать на столе по факту |
| Q2 | **Зачем это вообще?** | Мотивацию, боль, подоплёку |
| Q3 | **Как поймём, что готово?** | Чеклист приёмки — спорные моменты отсекаются сразу |
| Q4 | **Как видишь архитектуру?** | Стек, подход, твои хотелки |
| Q5 | **С чего начнём?** | MVP, первый рабочий прототип |
| Q6 | **Что нужно?** | Файлы, API, библиотеки, данные |
| Q7 | **Где может посыпаться?** | Риски, граничные случаи, узкие горлышки |
| Q8 | **Какой контекст дать AI?** | Бэкграунд, ссылки, спеки, примеры |

> **Железное правило:** не задаём вопрос, если ответ уже есть. Сказал «сделай сам» — не достаём, используем дефолты.

### Шаг 2 — Контекстный инжиниринг (5-Layer Stack)

Архитектура, которую Google DeepMind и Anthropic признали **стандартом 2025-2026**:

```
┌─ Layer 1: Системный промпт ──────────────────────┐
│  Ты — senior Python-разработчик.                 │
│  Используешь pep8, typing, pytest.               │
│  Без шаманства с лишними библиотеками.            │
├─ Layer 2: Память / Состояние ────────────────────┤
│  Проект: парсер Excel → JSON. openpyxl. 340 строк │
├─ Layer 3: Контекст / Поиск ──────────────────────┤
│  src/parser.py — текущая логика                   │
│  tests/test_parser.py — что уже покрыто тестами   │
├─ Layer 4: Инструменты и API ─────────────────────┤
│  ✅ openpyxl, pathlib, re  ❌ pandas, numpy       │
├─ Layer 5: Формат результата ─────────────────────┤
│  1. Модифицировать src/parser.py                  │
│  2. Дописать тесты на новые кейсы                 │
│  3. Показать diff                                 │
└──────────────────────────────────────────────────┘
```

### Шаг 3 — Промпт склеился → в Codex CLI

Всё. Можно отправлять. Контекст упакован, AI не будет додумывать.

```bash
ALL_PROXY=socks5h://127.0.0.1:10808 codex exec \
  -m gpt-5.3-codex \
  -s danger-full-access \
  -c skip_git_repo_check=true \
  --dangerously-bypass-approvals-and-sandbox \
  "$(cat prompt.md)"
```

## 🧩 Библиотека методик — всё в одном флаконе

TCE не замыкается на Тарике. Мы собрали **лучшие мировые методики** и прикрутили друг к другу:

| Методика | Когда тащить | Как стыкуется |
|----------|-------------|---------------|
| **8Q Тарика Шехипара** | Размытая хотелка, новый проект | 🔟 База, от которой пляшем |
| **GROW** (Whitmore) | Надо быстро сделать первый шаг | ➕ Q1→G, Q7→R, Q4→O, Q5→W |
| **5-Layer Context Stack** | Сложная архитектура, много файлов | 🧱 Скелет контекста |
| **Anthropic Context Engineering** | Промпт в проде, каждый токен на счету | 💰 Context Budgeting — экономия |
| **SMART** | Критерии приёмки | ✅ Проверка: Specific, Measurable, Achievable, Relevant, Time-bound |
| **5W2H** | Быстрая постановка, «сделай сам» | 📋 What/Why/Where/When/Who/How/How much |
| **SCQA** (Minto) | Баги, инциденты, проблемы | 🐛 Situation → Complication → Question → Answer |

Подробный разбор — в [`SKILL.md`](SKILL.md#библиотека-методик).

## 🔄 NC777 — кто за что отвечает

К каждой задаче TCE прикрепляет **ролевой конвейер** NC777 — операционную систему для AI-агентов:

| Сложность | Кого зовём | Когда |
|-----------|-----------|-------|
| 🟢 **Зелёная** | Developer → QA | Правим один файл, < 50 строк |
| 🟡 **Средняя** | Prophet → Architect → Developer → QA → Cleaner | 2–5 файлов, новая фича |
| 🔴 **Сложная** | Prophet → Architect → Reviewer → Developer → QA → Saboteur → Cleaner | Архитектурные перестановки |

Каждая роль знает свою задачу и не лезет в чужую. Полный разбор — [NiiyazG/NC777](https://github.com/NiiyazG/NC777).

## 🧠 Почему это реально работает

1. **Вопросы Тарика** выковыривают требования, которые ты сам в себе не осознавал
2. **5-Layer Stack** раскладывает инфу по полочкам — AI не тонет в простыне текста
3. **NC777** добавляет ролевую дисциплину — каждый этап знает свои границы
4. **Context Budgeting** экономит токены — AI не захлёбывается в мусоре
